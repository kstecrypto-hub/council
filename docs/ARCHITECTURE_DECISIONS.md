October 14, 2026 owner decision: BYOK/local inference is the MVP billing model, while optional Council-managed prepaid credits/provider-token resale may be investigated later. BYOK lowers Council's billing exposure but does not remove trusted API-key storage and revocation obligations. User-set Council budgets govern Council-authorized calls, not absolute provider bills. No Council payment/wallet system has been built or approved for MVP.

October 14, 2026 owner decision (ADR-14): combine Council's general-purpose agent loop with an **optional** Karpathy-style controlled experiment/evidence-feedback cycle inside ACT. Persist experiment/attempt evidence including failures; the member chooses KEEP/REVISE/DISCARD/INCONCLUSIVE. Worker experiments stay under parent authority/budget. No mandatory iteration/experiment quota, auto-optimizer, universal scalar score, or change to frozen checkpoint verification-only /work. Step 8 is not yet closed and no implementation was performed.

October 14, 2026 owner decision (ADR-15): each member governs all subagent processes/delegation inside its sandbox without a fixed Council worker-count/depth quota. The trusted runtime supervises **aggregate** sandbox resources through Docker Engine stats/events and supported cgroups limits. Configure a 2–5-second sampling target with initial 80%/90% sandbox-RAM pressure actions; monitor host/WSL2 VM RAM, disk/volumes, and GPU/VRAM separately. Telemetry is not proof against OOM; no raw Docker socket/control-plane credentials to agents. Whole-member crashes preserve identity and UNKNOWN effects. **Policy specified only; no monitor, scheduler or runtime tests implemented.**

## Completion policy

SPECIFIED means requirements have been written. IN DESIGN means named design decisions or integration details remain open. IMPLEMENTED requires executable behavior and a code reference. VERIFIED requires actual test execution, scope/environment, and result evidence. A test plan, stub, mock, static documentation check, or successful push cannot by itself complete a runtime step. No row above marks runtime work completed.

Step 7 is DESIGNED as a specification (approved October 14): initial configurable 70/25/5 development/review/orchestration-finalization proposal, equal monetary member development shares, user-authorized per-phase token/cost limits, default two remote calls/provider, one local inference job, three recovery retries (5s/30s/120s), approximately 20% RAM headroom adjusted by observed runtime needs, Part 5 event-clock-first reservation locking and explicit Pause/Stop state transitions. Mandatory periodic private-work slices were superseded; budget exhaustion preserves an incomplete member and never forces readiness. Provider rate/price/model-compatibility adapters, Docker enforcement, actual PG migrations and all runtime/concurrency/recovery tests remain NOT STARTED / NOT RUN. Steps **3, 4 and 5 are now DESIGNED as specifications** (October 14); normalized record constraints, versioned commands/state/frontier guards, and canonical/external transaction boundaries are reconciled. Runtime SQL migrations, generated DTOs, backend enforcement, connection/RLS tests, provider/GitHub/Docker integrations, and all concurrent/failure-injection tests remain NOT STARTED / NOT RUN. Step 8.1 specifies member-directed optional experimentation. ## Required runtime evidence (all pending)

- [ ] A one-slot execution admits the next eligible member once the current member reaches the milestone, blocks, safely yields, or exhausts its authorized phase budget; exhaustion never implies checkpoint readiness. No mandatory periodic private-work rotation is required.
- [ ] Phase token estimates are displayed only as uncertain forecasts, separately from user-approved quotas and metered usage; they never silently adjust the hard budget.
- [ ] Missing/failed members cannot silently shrink Council or pass either arrival or sealed-review barriers.
- [ ] Public opening checks all exposed refs/history/surfaces; partial/unknown transitions remain guarded; failed private closure prevents new unpublished commits; prior exposure is never claimed erased.
- [ ] Sealed reviews do not leak via repository commits, gateway, retrieval, caches, or member context before reveal.
- [ ] Peer test code cannot write another persistent workspace, continuation state, credentials, or protected acceptance definitions.
- [ ] Unknown inference allows safe unrelated progress with retained accounting; unknown writes are not blindly repeated; uncertain authority fails closed.
- [ ] Simultaneous member/worker/Orchestrator requests cannot overspend or consume protected review funds; timeout does not refund uncertain dispatched usage.
- [ ] Delayed commits, rollback, duplicate/out-of-order outbox delivery, and snapshot/SSE races cannot lose canonical events or falsely advance projections.
- [ ] Restored framework state cannot override canonical permissions, current epochs, or external-operation outcomes.
- [ ] New messages/actions race with /done and closure without being missed; deferred tests do not become passes.
- [ ] Processed clarification strength/scope is preserved; branch-local normalization memory does not influence unauthorized branches.
- [ ] Retained lessons resolve evidence after a fresh archive checkout without the temporary database; broken references prevent teardown.
- [ ] Comparative experiments and ablations run with fixed evaluation, full spend accounting, and failure/regression reporting.
