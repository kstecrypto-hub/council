## October 15 — Owner-approved unified trust, local OpenAI Moderation safeguards and command-only exchange (Steps 3–5)

**Accepted architecture direction — ADR-19 through ADR-21 (not design closure):**
- **ADR-19 / Unified trusted control plane.** One modular trusted Council application owns the command processor, authorization decisions, Orchestrator workflow, checkpoint and operation/outbox coordination. Keep privileged host Docker broker, member-private containers/storage, PostgreSQL access, and snapshot Git authority as separate security boundaries rather than granting the monolith or agents unrestricted host privileges. One customer-owned deployment; no vendor-source hosting.
- **ADR-20 / Local safety reasoning layer.** Use an open-weight **OpenAI OpenAI Moderation API** inference worker on the customer's approved infrastructure to classify relevant *semantic* content/commands under a pinned customer policy. Pair it with **mandatory deterministic** caller identity, scope, recipient, budget, path/content hashes and network/egress checks. The model cannot grant permission, reliably inspect raw binary files, prove absence of leaks, or replace network sandboxing. No silent policy bypass if guard unavailable; mark affected new actions BLOCKED/REVIEW. omni-moderation-latest has a nominal API access deployment requirement, so hardware/admission and configured local inference capacity remain IN DESIGN.
- **ADR-21 / Command-only member exchanges, no file-message bundling.** Members only ask for and receive peer information using narrow *typed commands* at the IRC-inspired checkpoint bridge. They have **no arbitrary SendFile/attachment/upload/peer Git path operation**; the trusted server selects actual export/response bytes solely from pre-authorized immutable manifests and serves bounded read-only content. File/artifact results contain no attached/automatically following chat messages. Any later peer comment must be a separate authorized message command, not part of the file response. Exact temporal meaning of the owner's "files can't be followed by messages" remains one semantic issue to confirm before locking the protocol.

This establishes the deployment architecture needed for the full evidence-grounded Council product: five independent candidate workspaces, semantic barriers, sealed independent reviews, evidence-linked challenges, disposable verification-only work, honest failures/unknown outcomes, customer-owned accepted output and opt-in retained knowledge. **NOT another unstructured five-model group chat**. [Full deployment design](STEPS_3_TO_5_DEPLOYABLE_ARCHITECTURE_2026_10_15.md). Steps 3–5 stay **REOPENED IN DESIGN**, with physical DTOs/schema/recovery still to reconcile. **No implementation, tests, or empirical benchmarks run; do not add any.**

## October 16 — ADR-25: One domain-agnostic integrated deliverable and five-member re-review

**Owner-approved Step 8.4 defining workflow:** five equal members independently build/investigate (not necessarily five production-complete versions), then conduct an evidence-grounded final comparison under the existing all-five sealed-review and command-only gateway protocol to identify **why and where each approach is stronger**, compatibility/conflicts, failed methods and valuable conclusions. The result is a **versioned Integration/Synthesis Blueprint**, not merely a winner or five unconnected results. A distinct **non-voting Final Integration/Synthesis LLM** uses a **new, explicit authorized integration workspace/source-read grant and user-approved integration allowance** to build **ONE integrated final deliverable**, combining defensible contributions and maintaining evidence traceability. The **same five original members independently perform sealed evaluation of the actual new integrated result**; new versions require applicable new checks/reviews. The six-month-plus premortem examines the integrated result and provisional report; real user acceptance/verified final archive remains separate. **ALL DOMAINS:** for research the integrator synthesizes one sourced analysis/report/protocol; for engineering one integrated design; for software one working codebase; and other Project Contract artifacts likewise. No hallucinated results, claimed completed tests or unapproved company data sharing.

A member's completed negative investigation can provide critical evidence and serve as a genuine fifth reviewer; it is not a working candidate and does not satisfy earlier implementation-ready barriers. A merely blocked/budget-exhausted member is not concluded. This final-submission gate is explicitly distinct from normal earlier checkpoint milestones. The Orchestrator remains neutral, the integrator is not a sixth voting member and no model automatically accepts output. **The original configurable 70/25/5 spend proposal requires explicit user-approved integration/re-review allocation and must not silently treat 5% as sufficient.**

## October 16 — ADR-26–29 approved Step 8.4 interface refinements

**ADR-26 — Bounded Integrator discretion.** The non-voting Final Integrator may make evidence-grounded technical or methodological decisions within the approved Blueprint/Project Contract and priorities; records alternatives, compatibility, limitations, source citations, provisional choices, exact produced revisions and any substantive deviation. Majority votes do not establish truth. New requirements, scope, egress, permissions or spending require explicit user approval.

**ADR-26 owner-approved refinement — Council recommendation governs direction:** The five independent Council members are the primary intellectual decision-makers for **which** architectural/research/engineering direction is favored and why. Embed a **Council Decision Register** in the versioned Integration Blueprint, preserving authentic independently sealed pre-discussion positions (where available), final post-discussion positions, changes of mind with reasons, source/evidence lineage and correlation, comparative strengths, Council-recommended direction and every material minority objection. Convergence gets **qualitative extra weight** when evidence/requirements do not discriminate, but neither 4/5 nor 5/5 is proof; a single verified counterexample can outweigh a majority. **The Integrator follows the Council recommendation by default**, owns bounded implementation/how decisions, and may materially depart only with a traceable evidence-/compatibility-based deviation record for original five-member re-review. Not an invented weighted voting formula, sixth reviewer, automatic veto or a fresh Integrator high-level election. The user controls material scope/permissions/budget/acceptance changes. [Authoritative ADR-26 update](STEP_8_4_COLLECTIVE_SYNTHESIS_AND_FINAL_INTEGRATION.md#91-adr-26--bounded-intellectual-discretion-for-the-final-integrator). **Design only; implementation/testing NOT STARTED/NOT RUN.**

**ADR-27 — Protected project-specific budget pools.** Supersede former setup default **70% development / 25% review / 5% orchestration/finalization** for Council's mandatory integrated result. Propose and obtain user approval for *five distinct protected chargeability scopes*: (1) member development; (2) checkpoint comparison; (3) Final Integrator synthesis/execution; (4) five-member integrated output review/revisions and premortem; (5) orchestration/report/archival overhead. No universal replacement percentages approved, no silent borrowing, and integration admission requires protected minimum subsequent review allowance. Existing reservation/UNKNOWN liability and versioned user top-ups remain.

**ADR-28 — Version-bound re-review.** First integrated product gets five independent sealed real reviews. Proven non-substantive/equivalent edits may preserve only evidenced applicability; localized substantive edits require five new independent **sealed delta reviews** of exact updated version and impacted dependencies; broad/high-risk/uncertain impact triggers five new **full** sealed reviews. Prior PASS never silently transfers to new material; model assertion of equivalence is not proof.

**ADR-29 — Sealed five-member premortem.** All five original members independently evaluate the same pinned integrated deliverable and provisional report revision, withheld until **five actual submissions and atomic reveal** in a separate `SEALED_PREMORTEM` round. Hypothetical six-month-plus failure mechanisms are not observed future evidence. Material changes invalidate affected applicability and require scope-appropriate five-member reconsideration.

These refine approved Step 8.4, not the other Council decisions.
